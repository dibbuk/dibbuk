# Запуск бота на VPS

Пошагово, от пустого сервера до работающего бота. Ориентир — Ubuntu 24.04,
на других дистрибутивах меняются только команды пакетного менеджера.

Весь путь занимает минут пятнадцать.

---

## Что понадобится

| Что | Зачем | Обязательно |
|---|---|---|
| VPS с Ubuntu 24.04 | Хост для бота | да |
| 1 ГБ RAM, 1 vCPU, 10 ГБ диска | Минимум для статики; для анимации лучше 2 ГБ | да |
| Токен от @BotFather | Доступ к Bot API | да |
| Telegram Premium на аккаунте владельца бота | Только для сборки картинки в сообщении | нет |

**Про порты:** бот работает на long polling и сам ходит к `api.telegram.org`.
Входящие соединения ему не нужны, пробрасывать порты и настраивать nginx не требуется.

**Про расположение VPS:** если сервер стоит в России, доступ к `api.telegram.org`
может быть нестабилен. Проверьте это на шаге 4 до того, как настраивать всё остальное.

---

## Шаг 1. Создать бота

В Telegram напишите [@BotFather](https://t.me/BotFather):

1. `/newbot`
2. Имя бота, которое увидят люди, например `Эмодзи из картинки`.
3. Username, обязан оканчиваться на `bot`, например `my_emoji_cut_bot`.

BotFather пришлёт токен вида `1234567890:AA...`. **Это пароль от бота, не публикуйте его.**
Если токен утёк, отзовите его командой `/revoke` и получите новый.

Там же задайте список команд, чтобы они показывались в меню:

```
/setcommands
```

Выберите бота и вставьте:

```
start - Начать
help - Как это работает
buy - Тарифы
```

---

## Шаг 2. Решить вопрос с мозаикой

Бот умеет присылать картинку, собранную из кастомных эмодзи прямо в тексте сообщения.
Это сильный демо-приём, но Telegram разрешает его боту **только** при одном из условий:

- у владельца бота есть **Telegram Premium**, либо
- боту куплен юзернейм на **Fragment**.

Что важно понимать: **на создание самих паков это не влияет**. Паки создаются
и раздаются по ссылке в любом случае, без Premium у кого бы то ни было.
Без выполнения условия отключится только сборка картинки в сообщении.

Если условие не выполнено, бот сам это обнаружит при первой попытке, погасит
функцию на весь процесс и один раз напишет в лог, что нужно сделать.
Можно и выключить заранее, поставив `ENABLE_MOSAIC=false` на шаге 7.

## Шаг 3. Подключиться к серверу и обновить систему

```bash
ssh root@ВАШ_IP
apt update && apt upgrade -y
```

---

## Шаг 4. Поставить зависимости

```bash
apt install -y python3 python3-venv python3-pip ffmpeg git
```

Проверьте три вещи. Все должны пройти без ошибок:

```bash
python3 --version                    # нужно 3.11 или новее
ffmpeg -encoders | grep libvpx-vp9   # нужен кодек для анимации
curl -s -o /dev/null -w '%{http_code}\n' https://api.telegram.org  # ожидаем 302
```

Если `python3 --version` показывает 3.10 или старее, дистрибутив слишком старый.
Проще всего пойти по пути с Docker из раздела ниже, он не зависит от версии системного Python.

Если `curl` не отвечает или висит, значит с этого сервера Telegram недоступен.
Дальше идти смысла нет, меняйте площадку.

---

## Шаг 5. Создать отдельного пользователя

Бот не должен работать от root. Это единственная строчка защиты, которая
реально стоит своих тридцати секунд.

```bash
adduser --system --group --home /opt/dibbuk dibbuk
```

---

## Шаг 6. Выложить код

```bash
git clone https://github.com/dibbuk/emopack_bot.git /opt/dibbuk/app
cd /opt/dibbuk/app
```

Репозиторий приватный, поэтому сервер попросит авторизацию. Простой путь —
[персональный токен GitHub](https://github.com/settings/tokens) с правом `repo`:
вставьте его вместо пароля, логин обычный. Аккуратный путь — deploy key,
он даёт доступ только к этому репозиторию:

```bash
ssh-keygen -t ed25519 -C dibbuk-deploy -f ~/.ssh/dibbuk -N ""
cat ~/.ssh/dibbuk.pub
```

Добавьте вывод в настройки репозитория, раздел Deploy keys, и клонируйте по SSH:

```bash
GIT_SSH_COMMAND="ssh -i ~/.ssh/dibbuk" \
  git clone git@github.com:dibbuk/emopack_bot.git /opt/dibbuk/app
```

Соберите виртуальное окружение и поставьте бота:

```bash
python3 -m venv /opt/dibbuk/.venv
/opt/dibbuk/.venv/bin/pip install --upgrade pip
/opt/dibbuk/.venv/bin/pip install /opt/dibbuk/app
```

Пакет установлен в окружение, поэтому `python -m bot.main` запустится
из любой директории. Осталось отдать каталог владельцу:

```bash
chown -R dibbuk:dibbuk /opt/dibbuk
```

---

## Шаг 7. Прописать настройки

```bash
cp /opt/dibbuk/app/.env.example /opt/dibbuk/.env
nano /opt/dibbuk/.env
```

Обязательна ровно одна строка, остальные можно оставить как есть:

```
BOT_TOKEN=1234567890:AA...
```

Что стоит поменять сразу:

| Переменная | Значение по умолчанию | Когда трогать |
|---|---|---|
| `FREE_DAILY_LIMIT` | `5` | Сколько паков в сутки бесплатно |
| `BRANDING_SUFFIX` | `"\| @{bot}"` | Приписка в названии пака, ваш главный канал роста. Кавычки не убирайте |
| `STARS_PRICE_UNBRAND` | `25` | Цена снятия ссылки с одного пака, в звёздах |
| `STARS_PRICE_SUBSCRIPTION` | `250` | Цена подписки на месяц, в звёздах |
| `ENABLE_MOSAIC` | `true` | Поставьте `false`, если Premium у владельца нет |

Закройте файл от посторонних, в нём лежит токен:

```bash
chmod 600 /opt/dibbuk/.env
chown dibbuk:dibbuk /opt/dibbuk/.env
```

---

## Шаг 8. Пробный запуск

Перед тем как заводить службу, убедитесь, что бот вообще поднимается:

```bash
sudo -u dibbuk bash -c 'set -a; . /opt/dibbuk/.env; set +a; \
  exec /opt/dibbuk/.venv/bin/python -m bot.main'
```

В логе должна появиться строка `запускаюсь как @ваш_бот`. Напишите боту `/start`
в Telegram и пришлите любую картинку. Если пришёл ответ с панелью настроек,
всё работает. Остановите пробный запуск сочетанием `Ctrl+C`.

Если видите `BOT_TOKEN не задан`, значит файл `.env` не прочитался: проверьте путь и права.

---

## Шаг 9. Завести службу

```bash
cp /opt/dibbuk/app/deploy/dibbuk.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now dibbuk
```

Проверьте состояние:

```bash
systemctl status dibbuk
```

Ожидаемое — `active (running)`. Служба переживает перезагрузку сервера
и сама поднимается после падения.

---

## Шаг 10. Смотреть логи

```bash
journalctl -u dibbuk -f          # живой поток
journalctl -u dibbuk -n 200      # последние 200 строк
journalctl -u dibbuk -p warning  # только предупреждения и ошибки
```

Две строки, которые стоит поискать сразу после запуска:

- `ffmpeg не найден в PATH` означает, что анимация отключилась. Вернитесь к шагу 4.
- `Telegram запретил боту отправлять кастомные эмодзи` означает ситуацию из шага 2.
  Паки при этом работают, отключилась только мозаика.

---

## Обновление

```bash
cd /opt/dibbuk/app
git pull
/opt/dibbuk/.venv/bin/pip install --upgrade .
systemctl restart dibbuk
```

Если клонировали по SSH, `git pull` тоже пойдёт через ключ:

```bash
GIT_SSH_COMMAND="ssh -i ~/.ssh/dibbuk" git pull
```

## Вариант через Docker

Если не хотите возиться с системным Python или он слишком старый.
ffmpeg уже внутри образа, ставить его отдельно не нужно.

```bash
apt install -y docker.io docker-compose-v2 git
git clone https://github.com/dibbuk/emopack_bot.git /opt/dibbuk
cd /opt/dibbuk
cp .env.example .env
nano .env          # впишите BOT_TOKEN
docker compose up -d
```

Логи и перезапуск:

```bash
docker compose logs -f
docker compose restart
```

Обновление:

```bash
git pull && docker compose up -d --build
```

## Если что-то не так

| Симптом | Причина | Что делать |
|---|---|---|
| `Unauthorized` в логе | Неверный или отозванный токен | Возьмите новый через `/token` у @BotFather |
| Бот молчит на сообщения | Запущено две копии сразу | `systemctl stop dibbuk` и убедитесь, что пробный запуск из шага 8 закрыт |
| `Conflict: terminated by other getUpdates` | То же самое, два процесса тянут обновления | Оставьте только один |
| Анимация не работает | Нет ffmpeg или собран без VP9 | Шаг 4, проверьте `ffmpeg -encoders \| grep libvpx-vp9` |
| Мозаика не приходит | Нет Premium у владельца и нет юзернейма с Fragment | Шаг 2 |
| `напишите боту /start и повторите` | Пользователь не запускал бота | Telegram требует этого для создания пака на его имя |
| Падает при больших картинках | Не хватает памяти под анимацию | Возьмите тариф с 2 ГБ RAM или уменьшите число колонок |
| Служба перезапускается по кругу | Ошибка на старте | `journalctl -u dibbuk -n 50` покажет причину |

## Что делать дальше

Бот запущен, дальше идёт продуктовая часть:

1. **Оплата звёздами.** Команда `/buy` уже выставляет счета. Чтобы вывести
   заработанное, понадобится 1000 звёзд и кошелёк на Fragment.
2. **Хранилище.** Сейчас состояние и квоты живут в памяти процесса, при
   перезапуске они обнуляются. Для боевой нагрузки подключите Redis или Postgres:
   интерфейс в `bot/storage.py` для этого и выделен.
3. **Продвижение.** Приписка в названии пака работает с первого дня, это ваш
   главный канал. Разбор остальных каналов в [конкурентном анализе](research/competitors.md).
